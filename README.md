# FilamentSwift

Cross-platform **Swift 6** bindings and host views for **Google Filament** (v1.77.3) with first-class glTF 2.0 / `.glb` support, PBR rendering, and native alpha transparency.

Designed for desktop and mobile: **macOS (AppKit / Metal)**, **Windows (Win32 / Vulkan)**, and **Linux (GTK 4 / Vulkan)**.

> **On Windows:** there are two demos, and the distinction matters.
>
> - **[`WinUI3Demo`](WinUIProjections/README.md) is the WinUI 3 demo.** A Win32 top-level
>   window with two children: one HWND for the Filament swap chain, one hosting a real
>   WinUI 3 XAML island (`Microsoft.UI.Xaml` controls). Built entirely in Swift — no C#,
>   no XAML markup — so it builds with **SwiftPM**, once the WinRT bindings have been
>   generated by `WinUIProjections/scripts/generate_winui_projection.py`. The interop is
>   modelled on a known working implementation; see
>   [`WinUIProjections/README.md`](WinUIProjections/README.md) for provenance and caveats.
> - **`Win32Demo` is a plain Win32 host window** (`CreateWindowExW`, `WNDCLASSEXW`, …) with
>   no WinUI 3 dependency. It needs no codegen step, so it stays the simplest
>   `swift run` / `bazel run` path.

## Features

- **Direct Swift 6 C++ Interop**: Zero Objective-C++ (`.mm`) boilerplate. Swift calls Filament C++ APIs directly via `-cxx-interoperability-mode=default`.
- **Precompiled Binary Distribution**: Automatically fetches official static libraries for macOS, Linux, and Windows with SHA256 verification (no source compilation needed).
- **True Alpha Transparency**: Built for floating 3D widgets, card overlays, and composited scenes over native OS host views.
- **First-Class GLB Support**: Built-in `gltfio` integration for loading PBR models with textures, animations, and skinning.
- **Both SwiftPM and Bazel**: Use either standard Swift Package Manager or Bazel Bzlmod (`MODULE.bazel`).

## Installation

### Swift Package Manager

Reference the package locally:

```swift
dependencies: [
    .package(path: "path/to/filament-swift"),
]
```

> **Note:** SwiftPM rejects packages that use `unsafeFlags` when they are consumed as a
> *dependency* of another package. This package needs `unsafeFlags` for the C++ interop
> include paths and the prebuilt Filament static libraries, so it works as a root package
> (or via `.package(path:)` / `.package(name:path:)`) but **cannot** be pulled in by version
> from a remote git URL. Use the Bazel route below for remote consumption.

If the prebuilt Filament SDK lives somewhere other than `.filament/` next to the manifest,
point `FILAMENT_DIR` at it:

```bash
FILAMENT_DIR=/opt/filament swift build
```

### Bazel (Bzlmod)

Add to `MODULE.bazel`:

```starlark
filament_repo = use_repo_rule("@filament_swift//:filament_repo.bzl", "filament_repo")
filament_repo(name = "filament")
```

## Resource Lifetime

Filament asserts if the engine is destroyed while asset entities are still alive, and
`deinit` is *not* main-actor isolated — it runs on whichever thread drops the last
reference. The Swift layer handles both:

- **`FilamentModel` retains its engine strongly**, so a loaded model always unloads before
  the engine that backs it goes away.
- **Teardown is routed through `FilamentMainActor.perform`**, which runs synchronously when
  already on the main thread and hops onto the main actor otherwise, instead of calling
  `MainActor.assumeIsolated` (which traps off the main thread).
- **`FilamentEngine.shutDown()`** releases everything eagerly and is idempotent. Call
  `FilamentModel.unload()` first if models are still attached.
- **`FilamentEngine` tracks the light IDs it creates**, so lights are destroyed during
  teardown and `removeLight(id:)` ignores unknown or already-removed IDs rather than
  importing a recycled entity.

## Architecture & Modularity

FilamentSwift is designed with a **clean modular architecture** that eliminates `#if os(...)` and `canImport(...)` conditional compilation spaghetti from Swift source code. UI host views and demos are cleanly isolated into dedicated platform modules:

Three SwiftPM packages, the way a standard library-plus-examples layout works:

```
filament-swift/                  # the library
├── Package.swift
├── Sources/
│   ├── Filament/                # engine, camera, lights, PBR controls, glTF loader
│   ├── FilamentC/               # C++ gltfio and Filament bridge
│   ├── FilamentAppKit/          # macOS AppKit NSView backed by CAMetalLayer
│   ├── FilamentWin32/           # Windows HWND host view (Win32 *and* WinUI 3 demos)
│   └── FilamentGTK/             # Linux GTK 4 drawing area host view
├── Tests/
│   ├── FilamentTests/
│   └── FilamentAppKitTests/
└── scripts/                     # ensure_filament.py

Examples/                        # demo apps, their own package
├── Package.swift                # depends on the library via .package(path: "..")
└── Sources/{AppKit,Win32,GTK4,WinUI3}Demo/

WinUIProjections/                # generated WinRT bindings, their own package
├── Package.swift
├── projections.json
├── scripts/generate_winui_projection.py
└── Sources/{CWinRT,WindowsFoundation,UWP,WinAppSDK,WinUI}/   # generated on Windows
```

Two structural notes:

- **Demos live in `Examples/`, not `Sources/`.** `swift build` at the root builds and tests
  only the library; the demos are free to take per-platform dependencies.
- **Generated bindings live in `WinUIProjections/`, not the library's `Sources/`.**
  SwiftPM can only read sources inside its own package root, so generated code has to be a
  target of *some* package — and keeping it separate means 30-odd machine-generated files
  are not sitting next to hand-written targets under `Sources/`.

Both **Swift Package Manager** and **Bazel** selectively build only the targets compatible
with your host platform. The WinUI 3 demo appears only once its generated bindings exist —
run `WinUIProjections/scripts/generate_winui_projection.py` first (Windows only).

## Quick Start (macOS AppKit)

```swift
import AppKit
import Filament
import FilamentAppKit

final class My3DCardView: NSView {
    private var filamentView: FilamentView!
    private var model: FilamentModel!

    override init(frame: NSRect) {
        super.init(frame: frame)

        // 1. Create Filament Metal view (handles resizing & Retina DPI automatically)
        filamentView = FilamentView(frame: bounds)
        filamentView.autoresizingMask = [.width, .height]
        addSubview(filamentView)

        // 2. Load .glb model
        model = FilamentModel(engine: filamentView.engine)
        if let glbURL = ModelDiscovery.discoverModels().first?.url {
            try? model.loadGlb(at: glbURL)
        }
    }
}
```

## PBR Render Controls

`FilamentPBRSettings` is a `Sendable` value describing the whole PBR pipeline, and
`FilamentPBRController` applies it to an engine. Host views only need to bind widgets to
the struct — all three demos do exactly that.

```swift
let pbr = FilamentPBRController(engine: filamentView.engine)   // also creates key + fill lights

// Live slider/checkbox binding:
pbr.mutate { $0.exposure = Float(slider.doubleValue) }

// Or apply a whole snapshot:
pbr.update(FilamentPBRSettings(toneMapping: .agx, bloomEnabled: true, bloomStrength: 0.25))

pbr.reset()   // back to .neutral
```

| Group | Settings |
| --- | --- |
| Lighting | `ambientIntensity`, `keyLightIntensity`, `fillLightIntensity`, `shadowsEnabled` |
| Tone mapping | `toneMapping` (Linear / ACES Legacy / ACES / Filmic / PBR Neutral / AgX / GT7), `exposure`, `contrast`, `saturation`, `vibrance`, `whiteBalance`, `tint` |
| Anti-aliasing | `antiAliasing` (None / FXAA), `multiSampleCount` (1/2/4/8), `dithering`, `hdrQuality` |
| Effects | `bloomEnabled` + `bloomStrength`, `vignetteEnabled` + `vignetteStrength`, `occlusionEnabled` + `occlusionMode` (SSAO/GTAO), `reflectionsEnabled` (SSR), `depthOfFieldEnabled` |

`update(_:)` only pushes the fields that actually changed, so it is cheap enough to call
from a slider callback. Changing a tone-mapping/grading field rebuilds the color-grading
LUT; the previous LUT is destroyed rather than leaked, and the engine dissociates it from
the view before destroying it.

**Unit gotchas** (both produce a badly blown-out image if you get them wrong):

- `exposure` is a **linear multiplier**. `1.0` keeps Filament's default photographic
  exposure (f/16, 1/125 s, ISO 100), which is calibrated for the ~100 000 lux directional
  lights the demos use. It is *not* `Camera::setExposure(Float)`, which hardcodes f/1.0
  and is roughly 100x brighter.
- `whiteBalance` is **-1 (cool) … +1 (warm)**, not Kelvin. Filament's docs note -1.0 is
  roughly 50 000 K; `0` is neutral.

## Demo Applications

FilamentSwift includes dedicated native demo applications for each supported platform that compile cleanly with both **Swift Package Manager** and **Bazel**:

| Platform | UI Framework | Backend | Target | SwiftPM Command | Bazel Command |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **macOS** | **AppKit** | Metal | `AppKitDemo` | `swift run --package-path Examples AppKitDemo` | `bazel run //Examples:AppKitDemo` |
| **Windows** | **WinUI 3** | Vulkan | `WinUI3Demo` | `swift run --package-path Examples WinUI3Demo` *(after codegen)* | `bazel run //Examples:WinUI3Demo` |
| **Windows** | **Win32** | Vulkan | `Win32Demo` | `swift run --package-path Examples Win32Demo` | `bazel run //Examples:Win32Demo` |
| **Linux** | **GTK 4** | Vulkan | `GTK4Demo` | `swift run --package-path Examples GTK4Demo` | `bazel run //Examples:GTK4Demo` |

### Native File Open Dialog, Mouse Camera Controls & Animation Selector

- **Native File Open Dialog**: Every demo includes an **Open Model…** button (and `Cmd+O` / `[O]` shortcut) that opens the platform's native file chooser (`NSOpenPanel` on macOS, `GetOpenFileNameW` on Windows, `GtkFileChooserNative` on Linux) to pick `.glb` files directly from disk.
- **Interactive Mouse Camera (`FilamentOrbitCamera`)**:
  - **Orbit (Tumble)**: Left-click and drag to rotate around the target.
  - **Pan (Truck / Pedestal)**: Right-click drag, Middle-click drag, or `Shift` + Left-click drag to pan the camera target in the view plane.
  - **Zoom (Dolly)**: Scroll wheel or trackpad pinch to zoom smoothly toward or away from the target.
  - **Reset View**: Click **Reset View** (or double-click the viewport) to return to the default camera pose.
- **Animation Controls**: If the active model contains glTF animations (skeletal bone skinning or node transforms), the app automatically reveals an **Animation Selector** dropdown displaying each animation's name and duration in seconds, alongside Play/Pause controls.

### Building All Targets

Using **Swift Package Manager**:
```bash
# library + tests
swift build
swift test

# demos
swift build --package-path Examples
swift run   --package-path Examples AppKitDemo
```

The test suite covers engine lifecycle, camera/viewport, light lifecycle, ambient-light
replacement (no `IndirectLight` leak), model loading and animation selection, model
discovery, PBR setting clamping and leak-sweeping, and regression tests for the two
teardown paths that used to abort the process (engine destroyed with a model loaded, and
release from a background thread).

Using **Bazel**:
```bash
bazel build //...
bazel test  //:FilamentTests
```
